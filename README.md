# 半人马AI-超级参谋团

独立 Electron 应用；使用 WANX 账号和 `centaurai-wanx` SDK。主持人与用户选中的专家是私有的 Octop 原生 Agent。用户确定目标和边界，主持人兼会议秘书组织、提炼，用户最终裁决；讨论通过原生 Teams / inbox 自动推进。

## 本地运行

1. 准备 Node.js 22 或更新版本，以及已支持超级参谋团接口的 WANX 服务。本仓库仅包含独立桌面客户端；WANX 服务端须支持 `/api/brainstorm` 的专家选择、会议控制和报告接口，详见 [WANX 接入说明](docs/wanx-integration.md)。账号、模型服务与主持人资源绑定由 WANX 管理；客户端读取可用模型，并保存每位参谋的选择。
2. 克隆仓库，在项目根目录安装并启动：

```sh
git clone https://github.com/finewood2008/centaurai-wanx-superadvisor.git
cd centaurai-wanx-superadvisor
npm ci
npm run build
npm start
```

3. 登录页填写 WANX 服务地址和与知君相同的账号。支持 HTTPS 或本机 HTTP 回环。首次登录选择常用专家；发起讨论时再选择本次参与者，随后输入主题。

执行 `npm run package:mac` 后，macOS Apple Silicon 测试包位于 `release/mac-arm64/半人马AI-超级参谋团.app`。本地测试包未正式签名、公证，不是生产发布。`npm run package:mac` 可重建。

## 在 WANX 启用应用

应用 ID 是 `super-advisory`，能力声明是 `chat / teams / brainstorm / zhijun_context`。平台管理员需要部署并授权使用者账号，沿用 SDK 已有应用管理接口：

```sh
read -s 'WANX_ADMIN_PASSWORD?WANX 管理员密码：'
export WANX_ADMIN_PASSWORD
node tools/enable-application.mjs http://127.0.0.1:8088 管理员账号 使用者账号
unset WANX_ADMIN_PASSWORD
```

脚本读取环境中的密码，不保存密码或 token；使用 WANX 应用管理接口注册产品、启用部署并授权指定现有账号。不创建另一套账号，不修改知君数据。首次运行需有 WANX 用户管理和应用管理权限；已存在的产品会核对能力并保留资源绑定。

## 使用说明

- 「参谋团设置」选择 2–12 位常用专家，并为每位参谋选择使用的模型。选项从 WANX 已启用的对话模型读取；WANX 专家库提供八类头脑风暴预设，并可选择其他现有模板。
- 「技能市场」通过 WANX 读取 SkillHub 专家卡片，导入调用原有模板安装器，保留工作流与技能。保存后可以邀请该专家参会。
- 新讨论可以从常用专家中选择本次参与者。每场保留自己的成员快照，更换默认专家不会改掉旧会议名单。
- 参谋团可保存每位专家的模型选择，不能新增模型、配置服务商或密钥，也不调用服务商写入接口。服务端拒绝不在当前 WANX 可用列表中的模型；正在讨论或成员仍在执行任务时不能修改配置，保存后后续派工使用新选择。主持人模型继续沿用 WANX 应用部署绑定。
- 输入主题后先与主持人简短沟通。每次回答一个关键问题，可以点选，也可以自由打字；尚未确认议程时不能向参谋派工。
- 主持人呈交本场目标、条件和议程，用户确认后开始。参谋围绕已确认范围自动研究，普通阶段简报无需用户逐次点选。
- 每次派工只针对一个问题或前序观点，参谋逐个回应、质疑、修正；主持人等当前参谋回报后再请下一位。用口语说明一个具体观点、理由和对你的影响，不设固定字数上限，必要的细节可以展开。
- 新发言使用打字机效果依次呈现；「显示本条全文」可直接展开当前发言。历史记录完整显示，播放期间仍可打字，系统减少动态效果时直接显示文字。
- 关键事实、目标取舍和最终方案使用判断卡。选项来自当前讨论，选择或文字反馈会进入下一轮实际任务；用户没有回答时不默认替他选择。
- 最终方案可点选采纳、继续比较，或打字后点击「以这段话裁决」。普通发言和主持人简报不会被记录为最终采纳。
- 暂停阻止后续派工，在途成员回答仍可保存。结束后本次讨论不能恢复。
- 采纳最终方案或结束会议后，会自动形成会议报告。报告包含你的裁决、目标与条件、核心观点、分歧、建议行动、待确认问题及参考资料；没有裁决时会如实注明。
- 点击「查看会议报告」预览，或「导出 Word 文档」选择保存位置，得到可编辑的 `.docx`。可切换回讨论记录；已经结束的旧会议也可生成报告。建议的负责人和时间不代表已分配任务，缺失内容标为待确认或未记录。
- 「调整重点」回到会前沟通；「请呈交方案」让主持人整理已有观点供用户判断。
- 知君资料按话题读取同一账号的记忆、已确认理解、知识库和对话历史，显示来源及性质。关闭引用或排除来源会暂停讨论，继续时采用新的范围。先前已经进入模型的内容和已保存消息不会被撤回。
- 服务重启后未完成的讨论显示「等待恢复」，用户可手动继续。
- 升级前未确认目标的旧会议先回到会前沟通，保留历史记录；结束的会议仍保持结束。
- 知君未初始化或部分服务不可用时，显示提示，仍可从主题展开讨论。
- 当前客户端不接入新产品的跨网络盒子身份；盒子/P2P 和真实模型效果需要单独联调。

## 代码结构

- `src/`：登录、专家设置、讨论与探索成果的 React 界面。
- `shell/`：Electron 主进程、受限 IPC 和 WANX SDK 会话；登录 token 保留在主进程。
- `tests/`：主进程会话、语音播放和探索成果内容的回归测试。
- `tools/enable-application.mjs`：沿用 WANX 应用管理接口启用产品并授权现有账号。
- `vendor/`：本客户端使用的 WANX SDK 安装包及版本记录。
- `assets/`：暖白朱砂「参」启动图标；[设计说明](DESIGN.md)记录视觉规范。

## 验证

```sh
npm test
npm run build
```

`npm test` 使用实际 SDK 和本地模拟 HTTP / WebSocket 服务，验证会话、报告导出、账号变化、token 隔离、语音播放及探索成果内容。`npm run build` 执行 TypeScript 检查和 Vite 构建。两者也可通过 `make all` 一起运行；提交前执行一次 `make install-hooks` 启用相同检查。

WANX 平台的集成测试与运行数据保留在平台开发仓库。本客户端不包含平台数据库、账号数据或真实讨论记录；客户端测试通过不等于生产 WANX、真实模型或盒子/P2P 联调通过。

探索成果按「目前最重要的判断 / 核心观点 / 分歧与风险 / 建议下一步 / 用户意见或裁决 / 待确认事项」组织，复用会议报告草稿。知君资料默认展示实际引用内容，可展开出处；记忆的原始对话主题、知识库文件名与来源性质可查看。
